Python 后端框架。AI 智库用它来接收请求、处理逻辑、返回分析结果。

阶段 10 · 5 月 22–23 日
分屏联动大战 Split-View Sync Battle
📅 5 月 22–23 日 🐛 5 轮调试
  • 根因 1： window.map 不是 Leaflet 对象 — let map 在函数作用域内从未分配给 window
  • 根因 2： map.off('move') 移除了所有移动处理程序，包括 Leaflet 内部的 — 完全破坏平移/缩放
  • 根因 3： 热力图数据包含来自 Box-Muller 极值的 5 个 NULL 坐标点
  • 根因 4： const MR_HEATMAP 在首次使用后声明 — 时间死区错误
  • 构建 Playwright 自动化浏览器测试以验证分屏行为端到端
  • 最终修复：命名处理程序引用 + 安全事件解绑 + NaN 坐标过滤
5 轮调试。每个修复揭露下一个更深的 Bug。TDZ Bug 最狡猾 — 无错误抛出，只是运行时静默失败。

CMO 不想要原始网络指标 — 他们想要商业结果。每个功能决策都经过"CMO 在周一早上会真正问这个问题吗?"的过滤。
🔄
增量优于一次性
阶段 6 证实了这一点。在一次提交中更改整个视觉系统 — 字体、间距、颜色、布局 — 造成混乱。每个后续重新设计都在小的、可审视的增量中进行，每个阶段后有检查点。
🐛
命名事件处理程序不可谈判
调用 map.off('move') 有匿名函数会移除该类型的所有处理程序 — 包括内部 Leaflet 的。始终存储处理程序的引用，并使用 map.off('move', namedHandler) 以安全解绑。
🌍
真实数据改变认知
从圆形标记切换到真实 GeoJSON 边界，从合成站点网格切换到高斯 + 走廊放置，即使底层数据相同，也将 Dashboard 从"演示"转变为"生产就绪"— 在用户心中。
🔍
QA 必须扫描代码，不仅仅是 HTML
55 个未翻译的字符串隐藏在 JavaScript 模板字符串内。仅限 HTML 的 QA 工具完全错过它们。i18n 验证需要也解析 JS 字符串上下文 — 始终使用 JS 感知的正则表达式模式。
🎨
颜色承载语义
RSRP 热力图颜色从蓝绿改为红黄绿只用了 30 分钟。与领域专家相处的可信度收益瞬间 — 他们立即识别了行业标准信号质量惯例。
⚡
规模处用 Canvas 而非 DOM
CTO 网格的 146,000 个 DOM 元素会让任何浏览器崩溃。用直接像素操作的 Canvas 渲染使其平滑。教训：选择与你的数据密度匹配的渲染基元，而非编码便利。
🧪
自动化你会重新检查的东西
分屏同步在开发期间破坏了四次。在第三次破坏后构建 Playwright E2E 测试意味着第四次回归被 CI 捕获，而非演示中。自动化投资在第二次失败时就开始回本。
